# NICO SHELF v0.14.3 β

ニコニコ動画のマイリストを、Googleログインに対応した自分の音楽ライブラリとして検索・分析・整理するWebアプリです。

- **公開アプリ**: https://nico-shelf.shiokara-lab.workers.dev
- **構成**: Vite / vanilla JavaScript / Supabase（Google Auth + PostgreSQL + RLS）/ Cloudflare Workers
- **ニコニコ連携**: Tampermonkeyのログイン済みニコニコタブから、直接登録・差分同期・メタデータ取得
- **注意**: ニコニコの非公式APIを利用するため、API変更時に同期・登録が動かなくなる可能性があります。

## v0.14.3 の変更（歌唱候補・散布図）

- VoiSonaの **知声（Chis-A）** を既知の歌唱者として登録し、和文・英文名を同一キャラクターとして集計します。既存の配色辞書にあった東北ずん子・Lilyも歌唱者の判定辞書に追加しました。
- 判定辞書にない名前でも、タイトルの明示的な `feat.`、概要欄の `歌唱：` / `Vocal:` / `歌：`、タグの `歌唱：` などから**確認候補**として拾います。登録前の候補は自動集計されず、「歌唱者に要確認候補あり」で確認できます。
- `原曲：`、`イラスト：`、歌詞などの自由文は、未知の歌唱者として推測しません。既存の手動確定・保存済み歌唱者を優先します。
- 散布図は削除動画・非公開動画・公開状態が未確認の動画を除外。**表示点・有効件数・歌唱者凡例・Spearman順位相関**に含めません。元のDBやメモは保持します。
- `取得失敗` は削除と同義ではありません。古い初期データにある `Deleted video` / `Private video` だけは明示的なプレースホルダーを優先します。
- 動画情報を再取得できた場合は、古い `取得失敗` と仮のタイトルを更新できるよう改善しました。
- 新しい `src/app/scatter-availability.js` が必要です。**更新用ZIPでは新規ファイルもアップロード**してください。
- Supabase SQL・Google Auth・Tampermonkeyの更新は不要です。

## v0.14.2 の変更

- 歌唱者ランキングとマイリスト別比較に、表示人数「5・10・15・20・30・全員」を追加。デフォルトは15人。
- 音楽の変遷で「5・10・20・30・すべて」を選択可能に。これまでの5本固定ではなく、選択数だけ折れ線を描画。
- 多数の折れ線は「強調する項目」で特定キャラクターだけを目立たせられます。
- 散布図の凡例を15・30・全員から選択可能にし、凡例を押すとキャラクターで絞り込めます。
- 約30人分のキャラクター用近似色と歌唱者別名判定を追加。既存の色は維持。
- 未設定キャラクターには名前由来の安定した自動色（非公式色）を表示。未判定は灰色です。
- Supabase SQL、Tampermonkey、Cloudflare設定の変更は不要です。

## v0.14の新機能

1. **キャラクター固有色** — 歌唱者ランキング、リスト別傾向、音楽の変遷の折れ線・横棒・ヒートマップで一貫した色を使用します。音街ウナの別エンジン表記も共通色です。
2. **散布図ページ** — 再生数・コメント数・いいね数・動画時間・投稿時期をX/Yに選び、歌唱者別に色分けして確認できます。各点から動画詳細を開けます。
3. **欠損値を区別** — 未取得の情報は「0」とみなさず描画対象から除外。何件が描画されたか明示します。再生数などは対数目盛でゼロも扱います。
4. **可読性維持** — 色・散布図の集計・散布図の描画を独立モジュールに分割し、回帰テストを追加しました。

キャラごとの色は視覚的な近似値を含み、すべてが公式指定のHEX値とは限りません。詳細と編集場所は `docs/SCATTER.md` を参照してください。

## v0.13から引き継いだ機能

1. **音楽の変遷：推移グラフ** — ヒートマップに加え、複数項目の折れ線・注目項目の横棒表示を追加。凡例から特定項目を強調でき、分類率もグループ別に表示します。
2. **歌唱者判定の精度改善** — 既存歌唱者情報・タグに加え、タイトルの `feat.` / `/ 歌唱者`、概要欄の `歌唱:` / `Vocal:` / `使用音源:` なども参照します。根拠は動画詳細画面で確認できます。
3. **誤判定を抑制** — 概要欄の単なる名前の言及や、歌唱以外のクレジットは原則として歌唱者に確定せず、要確認候補に残します。「歌唱者に要確認候補あり」フィルタから整理できます。
4. **分類根拠の改善** — ジャンル・雰囲気はタグに加え、概要欄の `ジャンル:` / `雰囲気:` など明示的な表記だけを参考にします。`作曲:` や `Music:` からの作曲者情報も補助的に抽出します。

**重要な限界**: これは保存されているテキスト情報からの推定であり、曲の音声を解析した判定ではありません。概要欄内の自由な言及をすべて歌唱者として採用しないのは誤判定対策です。歌唱者は動画詳細の「歌唱者を自分で修正」で最終確定できます。

## ローカル開発

Node.js 22以上を使用します。

```bash
npm install
cp .env.example .env.local
# .env.local に VITE_SUPABASE_URL と VITE_SUPABASE_PUBLISHABLE_KEY を設定
npm run dev
npm test
npm run build
```

Cloudflare Workersへの公開は既存の `wrangler.jsonc` を使います。**`service_role` キー・ニコニコCookie・個人のJSONバックアップをGitHubへコミットしないでください。**

## 既知の注意点

- マイリストの**表示順**は正確な登録日ではありません。投稿年も聴取年ではありません。
- 1曲に複数人が歌唱・複数タグが付与されるため、割合の合計は100%にならない場合があります。
- 未分類動画の分母を消さないため、グラフには**分類率（根拠を確認できた動画の割合）**を必ず併記しています。
- 追加の判定ルールは、意図しない誤判定を防ぐためテストとセットで変更してください。
- この開発環境では依存パッケージをインストールできず、Vite本番ビルドと実ブラウザ画面での最終確認は未完了です。Cloudflareのデプロイ後に確認してください。
