# NICO SHELF v0.6 β — ニコニコへの直接登録（クラウド版）

Googleログイン・Supabase・Cloudflare Workersを使うNICO SHELFの試作版です。v0.5の検索・ソート・差分同期・個人メモを維持したまま、**NICO SHELF画面からニコニコ本体への動画登録**を追加しました。

> **ベータ版です。** UI/ローカルロジックのテストは通過していますが、ニコニコ本番アカウントでの登録とTampermonkeyタブ間通信の実機確認は行っていません。非公開の内部APIの仕様変更で動作しない場合があります。最初は未登録の1件だけで動作確認してください。

## v0.5からの更新手順

1. **念のため** [NICO SHELF](https://nico-shelf.shiokara-lab.workers.dev) の「データと設定」→ JSONバックアップを保存。
2. `update` ZIPに含まれるファイルを [GitHub](https://github.com/5jfv9b7s/nico-shelf) の同じ相対パスに上書き。`src/main.js` ほかを更新し、`src/bridge.js`, `src/registration.js`, `bridge/nico-shelf-direct.user.js` を追加。
3. Cloudflare Workersの既存ビルド設定 `npm run build` → `npx wrangler deploy` のままでGitHub連携の自動デプロイを確認。**Cloudflare環境変数の変更は不要**です。
4. ChromeのTampermonkeyで **`bridge/nico-shelf-direct.user.js` を新しいスクリプトとして追加**。スクリプトのアクセス対象は`nico-shelf.shiokara-lab.workers.dev`と`www.nicovideo.jp`。両方でスクリプトが有効か確認します。**登録後にNICO SHELFのタブを再読み込みしてください。** 手元のv0.3ローカル用`nico-shelf-bridge.user.js`は無効にすることを推奨。v0.5のスナップショット用スクリプトはそのまま利用可能。
5. **今回の更新でSupabaseに新しいSQLを実行する必要はありません。** 既存v0.5の `playlists`, `videos`, `entries`, `user_meta` とRLSをそのまま使います。

## 使い方

1. ログインして「ライブラリ」→「＋ 動画を登録」を開く。
2. 動画IDまたはURL（例 `sm12345678`）を入力。登録先は既定の「自動：ぼかうた1 → 2 → 3」。**最近のお気に入りは自動登録しません**。登録先のプルダウンで明示的に選んだ場合だけ登録可能です。
3. 「① ニコニコと接続」を押す。開いたニコニコのタブで **「接続を許可」** を押す。タブは閉じない。
4. NICO SHELFに戻り、「② 登録状況を確認」を押す。現在のニコニコ側マイリスト件数と重複所属先、登録候補先を確認。
5. 別リストに同じ動画があれば「重複しても登録する」を明示的にチェック。登録先に本人がいる場合は二重登録しません。
6. 「③ ニコニコ本体に登録する」を押し、最終確認ダイアログで実行。
7. ニコニコ側で登録後のマイリストを再取得し、動画が存在することを**確認できたときのみ**Supabaseにも保存します。

### 仕組み・セキュリティ

- **Google OAuthとニコニコのログインは独立**しています。接続時のニコニコアカウントが対象マイリストの所有者であることを確認してください。
- Tampermonkeyスクリプトを**NICO SHELFとニコニコ両方のページ**で動かし、`GM_setValue` / `GM_addValueChangeListener` で同じブラウザ内の別タブへリクエストと結果を中継します。通常のWebページ間でニコニコCookieを送る仕組みではありません。
- Cookie・Google認証トークン・Supabase秘密鍵は連携スクリプトから送信しません。連携スクリプトの保存領域には動画ID、マイリストID、タイトル、処理結果などの情報が一時的に残ることがあります。
- 操作ごとに一意のランダムなセッションIDを用い、ニコニコ側のパネルで接続許可を求めます。登録前にはリモート側の所属と容量を再確認します。
- `ぼかうた1, ぼかうた2, ぼかうた3...` の形式に一致する数値IDのリストだけを自動登録候補にします。**公開版の他ユーザー向け登録順・登録先設定は今後の課題**です。
- ニコニコ側で書き込み成功 → Supabaseの更新失敗、という場合は登録を再試行せず、v0.5の**差分同期**でDBを整えてください。
- 通信タイムアウト時は、実際には書き込まれた可能性があります。登録先のニコニコを確認し、必要なら差分同期してください。**同じリクエストを自動再送しません。**
- 本機能は**PCのChrome + Tampermonkeyでの利用**を想定。モバイル端末ではTampermonkeyやニコニコCookieが使えない場合があります。
- 他人のアカウントを指定して操作する設計ではありません。ニコニコAPIは非公式のため運用・利用規約・レート制限を確認してください。自動的な大量登録には利用しないでください。

## 開発・テスト

`npm test`：19件のテスト（マイリスト順序・重複判定・同期データの正規化など）。
`npm run build`：ViteによりCloudflare Workers向け `dist` をビルド。

環境変数はv0.5と同じく、`VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` のみ。**`sb_secret_...` や`service_role`キーを公開しないこと。**

## 公開版の既知の課題

- ローカルでのロジックと構文は検証済みですが、**実際のニコニコ内部API書き込み、Tampermonkey連携、Supabase書き込みの一連の実機テストは未実施**。
- 曲名・歌唱者・タグのメタデータ自動補完は未実装。新規動画はニコニコで取得したタイトルまたは動画IDで保存。必要に応じて後でメタデータ同期する設計です。
- ワンボタン完全自動ではなく「接続→重複確認→確認して登録」の明示的な手順です。
- 公開一般ユーザー向けのプライバシーポリシー、アカウント削除、利用条件確認、インフラ保護などは別途対応が必要です。
