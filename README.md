# NICO SHELF v0.7.0 β — ワンクリック差分同期

GitHub → Cloudflare Workers → Supabase の構成で動く、個人別ニコニコマイリスト管理Webアプリです。v0.6.2の直接登録を維持し、**JSONファイルを経由しない差分同期**を追加しました。

## 新機能

1. **ニコニコ連携**を開き、「ニコニコと照合する」をクリック。未接続のときはニコニコのタブで1回だけ「接続を許可」。
2. アプリが対象マイリストを1つずつ取得（**全リスト取得成功が必須**）。動画詳細・コメント・再生数などを毎回取り直さず、登録一覧とタイトルだけを取得。
3. 動画IDごとに追加・削除候補とリスト内表示順を比較。**差分表示だけではSupabaseに一切書き込まない**。
4. 結果を確認して「差分を反映」を実行すると、既存の `apply_mylist_snapshot` RPC を使って所属と順番を一括更新。削除済みの所属は `present=false` の履歴として残し、動画本体のメモ・評価は削除しない。

- ニコニコ本体に動画を登録する機能は従来どおり。自動登録先は「ぼかうた1→2→3」で、最近のお気に入りには自動登録しません。
- 従来の手動JSON同期も「JSONファイルで同期する（予備の方法）」に残しています。
- **追加SQLやDBマイグレーションは不要**。v0.5の `202611090002_sync_snapshot.sql` が適用済みであることが前提です。
- ニコニコCookie／Google認証情報／Supabaseの秘密キーをTampermonkey経由で送信することはありません。接続済みニコニコのタブで、登録済みリストのID・タイトル等を読み取ります。

## 更新方法（v0.6.2 → v0.7.0）

1. 先に **NICO SHELF → データと設定 → JSONバックアップ**を保存。
2. `nico_shelf_v0.7_update.zip` を展開し、既存GitHubリポジトリ `5jfv9b7s/nico-shelf` の同じパスへファイルを上書き・追加。既存データをGitHubへ上げる必要はありません。
3. Cloudflare Workersの自動ビルド・デプロイが完了したことを確認。現在の `wrangler.jsonc`、環境変数、Supabase認証設定はそのままでOK。
4. ChromeのTampermonkeyダッシュボードで **v0.6.2の `NICO SHELF Direct Bridge` のスクリプトを編集**し、`bridge/nico-shelf-direct.user.js` の中身を全文貼り付けて保存。別のDirect Bridgeスクリプトを増やさず、**有効なのはv0.7.0だけ**にする。
5. 旧接続用ニコニコのタブを閉じ、NICO SHELFを `Ctrl+Shift+R` で再読み込み。
6. 「ニコニコとの差分同期」→「接続してニコニコと照合する」。ニコニコ側タブに **v0.7.0** のパネルが表示されていることを確認し、**接続を許可**。
7. 差分一覧が表示されたら、件数と動画IDの変化を確認。最初は **差分表示だけ試し**、意図どおりならバックアップ後に「差分を反映」。

公開中のサイト: https://nico-shelf.shiokara-lab.workers.dev

## 実装のポイント

- `src/bridge.js`: v0.6.2で動作したDOMイベント + TampermonkeyのGM共有ストレージ方式を継承。今回新しい通信方式へ切り替えていません。
- `bridge/nico-shelf-direct.user.js`: 既存の `inspect`、`register` に読み取り専用 `snapshot-list` を追加。**1リストずつ送る**ことで複数リストを巨大な単一メッセージにしません。APIが欠損・重複・HTTPエラー・不正なページングを返す場合、取得途中の結果を破棄します。
- `src/sync.js`: 各リストの取得結果を検証して完全な同期スナップショットを作る。差分確認後に他端末でDBが変わっても、動画IDと順序まで再比較します。
- `src/main.js`: 同期ボタン、進捗表示、全リスト完了後のプレビュー、元の手動JSONフォールバック。
- `supabase/migrations/202611090002_sync_snapshot.sql`: 従来のRPCを流用。**新しいSQLの実行は不要**。

## 動作確認と注意点

- `node --test tests/*.test.mjs`: 27件のローカルテスト（接続、登録先判断、ID差分、500件＋125件のAPI模擬取得、異常時停止など）。
- `node --check` によるJavaScript構文確認。
- Cloudflare本番ビルドは、作業環境から依存パッケージの取得がタイムアウトしたため未検証。Vite・Supabaseの依存構成自体はv0.6.2から変更していません。
- **実際のニコニコアカウントとTampermonkeyでの動作は未検証**。非公式APIへの依存があり、仕様変更の影響を受ける可能性があります。
- 途中まで取得できても、全リストの取得完了前に中断した場合は差分を生成・反映しません。
- ニコニコから削除された登録はDB上で履歴を維持しますが、バックアップを取ってから反映してください。
- 同期は**ユーザーがボタンを押す操作**で、常時・バックグラウンド・自動監視ではありません。ニコニコの接続タブが開いている必要があります。

## 開発実行

```bash
npm install
npm run dev
npm test
npm run build
```

Vite用の `.env.local` は `.env.example` を参照。`VITE_SUPABASE_PUBLISHABLE_KEY` は公開可能な鍵だけを設定し、SupabaseのSecret / service_role鍵を絶対に設定しないでください。
