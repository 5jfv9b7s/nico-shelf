# NICO SHELF v0.17.3

公開マイリストの公称件数より返却動画が少ない場合も、最終ページを確認できれば取得分をプレビューできます。例えば公称500件・取得499件なら、画面にその差を表示します。新規取り込みは確認できた499件を保存し、登録済みリストでは確認できた動画の追加・復元を反映します。既存動画の所属と順番を保持するため、新規・復元動画は末尾に加わります。応答に含まれなかった登録済み動画は画面で確認できます。

## v0.17.2からの更新

1. SupabaseのSQL Editorで `supabase/migrations/202611130001_public_mylist_partial.sql` を実行します。
2. 更新用ZIPのファイルを既存プロジェクトへ上書きし、通常のGitHub／Cloudflareの手順でデプロイします。
3. アプリを再読み込みし、「ぼかうた1」の差分を確認します。公称500件・取得499件の表示と、今回の応答に含まれなかった登録済み動画を確認できます。

このSQLは取得分だけを反映する保存処理を追加します。新しい画面は新RPCを利用するため、SQLを先に適用してください。Renderの取得処理は既存のものを使います。前回のゲートウェイ設定修正も含めています。

通信途中の失敗、ページ欠落、動画ID重複、取得中の公称件数変化はエラーになります。全件取得できたリストは従来の差分同期を利用します。PC側のTampermonkeyで500件取得できる場合は、そちらから全件を照合できます。

架空データによる500件／499件の再現、自動テスト222件、ビルド、ローカルPostgreSQL互換環境でのSQL動作を確認しました。実ブラウザの画面確認と本番環境の動作確認は未完了です。Renderが特定の1件を返さない原因は未解明です。

## v0.16.3 — 公開マイリスト同期のCloudflare互換性修正（2026-11-12）

**原因:** v0.16.2はCloudflare Workersが対応していない `fetch(..., { redirect: 'error' })` を指定し、外部HTTPリクエストの前に必ず例外が発生する状態でした。詳細: https://developers.cloudflare.com/workers/runtime-apis/request/

**修正:** `worker/index.js` を `redirect: 'manual'` に変更し、3xxレスポンスは自動追跡せずエラーにします。また、ネットワーク・JSON・API形式のエラーを分離して表示します。

1. `worker/index.js` を含む更新パッチをGitHubに適用します。Cloudflareのデプロイで **Worker本体（wrangler deploy）** が更新されたことを確認します。ブラウザのキャッシュ更新だけでは直りません。
2. `https://nico-shelf.shiokara-lab.workers.dev/api/public-mylists/75327830?page=1` を開きます。成功なら `items` 配列を含むJSON。失敗時は `code` と `stage` のあるJSONになるので、その**コード部分だけ**を診断に使用できます。
3. NICO SHELFで公開リストを1つ選び「公開マイリストを照合する」を再試行します。複数リストの一部が非公開だったり取得に失敗した場合、同期全体を中止します。マイリストへの追加・削除候補は差分プレビューで確認してください。

Cloudflareに新しい環境変数・DB変更・Tampermonkey更新は不要です。v0.16.2のレート制限バインディングは引き続き必要です。実際のニコニコ側の公開APIの応答までは、この環境から検証できていません。

## v0.16.2 — 公開マイリスト同期の503修正（2026-11-12）

v0.16.0〜v0.16.1の `/api/public-mylists/...` が、公開データの取得前にSupabase Authへ問い合わせ、接続・JSON解析の失敗で503を返す問題を修正しました。

- **公開マイリストの取得だけ**はSupabase Authへの再通信を行いません。ブラウザからSupabaseのアクセストークンをこの公開APIに送信する処理も削除しました。
- Workerは固定されたニコニコの公開APIだけを読み取ります。Cloudflareの `PUBLIC_MYLIST_RATE_LIMIT` バインディングでアクセス回数を制限します。`wrangler.jsonc` **を必ず更新**してください。
- このAPI自体は認証不要で、**他人も公開マイリストを読み取れます**。個人のNICO SHELFライブラリやメモにはアクセスできず、DBの保存・更新は従来のGoogleログイン・Supabase RLSに従います。
- Supabase用の **VITE_*** ビルド環境変数は引き続き必要です。旧版のWorker専用 `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` は公開同期には不要になりました（Cloudflareで後から削除可能）。
- 新たなSQL・Tampermonkeyの更新は不要。非公開リストの同期やニコニコ本体への直接登録は従来どおりTampermonkeyが必要です。
- 詳しい設定と制限事項は [`docs/EXTENSION_FREE_SYNC.md`](docs/EXTENSION_FREE_SYNC.md) を参照してください。Cloudflare→ニコニコAPIの実通信はデプロイ後に要確認です。

# NICO SHELF v0.16.0 β

ニコニコ動画のマイリストを、Googleログインに対応した自分の音楽ライブラリとして検索・分析・整理するWebアプリです。

- **公開アプリ**: https://nico-shelf.shiokara-lab.workers.dev
- **構成**: Vite / vanilla JavaScript / Supabase（Google Auth + PostgreSQL + RLS）/ Cloudflare Workers
- **ニコニコ連携**: Tampermonkeyのログイン済みニコニコタブから、直接登録・差分同期・メタデータ取得
- **注意**: ニコニコの非公式APIを利用するため、API変更時に同期・登録が動かなくなる可能性があります。

- **v0.16.2以降**: Worker専用のSupabase環境変数は不要です。`wrangler.jsonc` のレート制限バインディング設定が必要です。詳しくは [`docs/EXTENSION_FREE_SYNC.md`](docs/EXTENSION_FREE_SYNC.md)。
- 今回はSupabase SQLとTampermonkeyスクリプトの更新は不要です。

- OAuthを使った直接登録は、ニコニコ側の正式なクライアント発行方法・書き込み権限を確認できるまで保留です。API利用規約の確認と実ブラウザテストが必要です。

## v0.14.4 の変更（散布図の軸を拡張）

散布図の横軸・縦軸で、以下を選択できます。

| 区分 | 指標 | データの意味 |
|---|---|---|
| 動画の基本情報 | 再生数、コメント数、いいね数、動画時間、投稿時期 | ニコニコの動画メタデータ |
| 動画の基本情報 | **ニコニコのマイリスト数** | 動画がニコニコ全体で登録された回数（Supabase `videos.mylists`） |
| 再生数に対する反応 | マイリスト率、コメント率、いいね率 | 1,000再生あたりの件数 = 件数 / 再生数 × 1,000 |
| 自分のライブラリ | **自分の所属マイリスト数** | 自分のリストのうち、その動画が属するリスト数。ニコニコ全体の数とは異なる |
| 自分のライブラリ | 自分の評価（1〜5） | ユーザーがNICO SHELFで付けた星評価 |

- 率を計算するとき再生数が0件の場合は未計算となり、点を描画しません。未取得のメタデータも0とは区別します。
- 未評価（0）は、評価軸では非表示です。未所属の動画は、所属リスト数0として扱います。
- ニコニコのマイリスト数が不足している既存曲は、アプリのメタデータ補完から取得可能です（取得可能なAPI応答の場合）。
- `src/app/scatter.js` が数値変換と欠損値判定、`src/ui/scatter.js` が画面描画を担当します。
- **v0.14.3からの更新**: データをバックアップ後、更新用ZIPのフォルダ構造を維持してGitHubに上書きし、Cloudflareのビルドを確認してください。
- **Supabase SQLの変更とTampermonkeyの更新は不要**です。

4. **可読性維持** — 色・散布図の集計・散布図の描画を独立モジュールに分割し、回帰テストを追加しました。

キャラごとの色は視覚的な近似値を含み、すべてが公式指定のHEX値とは限りません。詳細と編集場所は `docs/SCATTER.md` を参照してください。

## v0.13から引き継いだ機能

1. **音楽の変遷：推移グラフ** — ヒートマップに加え、複数項目の折れ線・注目項目の横棒表示を追加。凡例から特定項目を強調でき、分類率もグループ別に表示します。
2. **歌唱者判定の精度改善** — 既存歌唱者情報・タグに加え、タイトルの `feat.` / `/ 歌唱者`、概要欄の `歌唱:` / `Vocal:` / `使用音源:` なども参照します。根拠は動画詳細画面で確認できます。
3. **誤判定を抑制** — 概要欄の単なる名前の言及や、歌唱以外のクレジットは原則として歌唱者に確定せず、要確認候補に残します。「歌唱者に要確認候補あり」フィルタから整理できます。
4. **分類根拠の改善** — ジャンル・雰囲気はタグに加え、概要欄の `ジャンル:` / `雰囲気:` など明示的な表記だけを参考にします。`作曲:` や `Music:` からの作曲者情報も補助的に抽出します。

**重要な限界**: これは保存されているテキスト情報からの推定であり、曲の音声を解析した判定ではありません。概要欄内の自由な言及をすべて歌唱者として採用しないのは誤判定対策です。歌唱者は動画詳細の「歌唱者を自分で修正」で最終確定できます。

## ローカル開発

Node.js 22以上を使用します。

```bash
npm install
cp .env.example .env.local
# .env.local に VITE_SUPABASE_URL と VITE_SUPABASE_PUBLISHABLE_KEY を設定
npm run dev
npm test
npm run check:imports
npm run build
```

Cloudflare Workersへの公開は既存の `wrangler.jsonc` を使います。**`service_role` キー・ニコニコCookie・個人のJSONバックアップをGitHubへコミットしないでください。**

## 既知の注意点

- マイリストの**表示順**は正確な登録日ではありません。投稿年も聴取年ではありません。
- 1曲に複数人が歌唱・複数タグが付与されるため、割合の合計は100%にならない場合があります。
- 未分類動画の分母を消さないため、グラフには**分類率（根拠を確認できた動画の割合）**を必ず併記しています。
- 追加の判定ルールは、意図しない誤判定を防ぐためテストとセットで変更してください。
- この開発環境では依存パッケージをインストールできず、Vite本番ビルドと実ブラウザ画面での最終確認は未完了です。Cloudflareのデプロイ後に確認してください。
