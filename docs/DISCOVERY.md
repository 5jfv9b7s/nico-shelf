# v0.11: 関連楽曲の探索モード

v0.10の関連曲判定に以下の切替を追加しました。ロジックは `src/app/related-videos.js` に集約し、UIは `src/ui/related.js` に分離しています。関連曲の判定対象は、ログイン中ユーザーの `buildLibraryRows()` から生成される動画だけです。

| モード | 歌唱キャラ | 作者・投稿者 | ジャンル | 雰囲気 | 共通タグ |
|---|---:|---:|---:|---:|---:|
| バランス | 3.5 | 2.2 | 1.6 | 1.3 | 1.0倍 |
| ジャンル・雰囲気重視 | 0.35 | 0.35 | 3.2 | 3.0 | 1.7倍 |
| 別の作者・投稿者を発掘 | 3.5 | 一致候補を除外 | 2.2 | 1.7 | 1.2倍 |

それぞれ歌唱者・作者・ジャンル・雰囲気の一致は最大2つまで加点、共通タグは希少な順に最大3つで採点します。共通タグの加点はライブラリ内の文書頻度から決めます。スコアは**相対順位用の任意値**で、音楽的な類似確率ではありません。

- `musical` はジャンル・雰囲気・共通の具体的タグが1件もない動画を候補にしません。
- `explore` は元動画と共通する作曲者・作者・投稿者名がある動画を除外します。作者の同一性を保証する機能ではありません。
- `unratedOnly` は評価済み（星1〜5）を候補から除外します。データベースの既存レコードは変更しません。
- 元動画・一般的なタグのみで一致した候補は、引き続き除外します。
- 同点は動画IDで安定的にソートします。
- UIで探し方を変えると、ダイアログ内の条件だけ再描画されます。Supabaseへの追加リクエストはありません。

# 関連楽曲の探索と分類根拠 — v0.10

## 目的

登録済みの動画を入口に、**現在ログインしているユーザー自身のライブラリ**から関連する作品を探します。
検索エンジンや音声モデルは使いません。あくまでタグ・歌唱者・作者などの**保存済みメタデータに基づく類似度**です。

## UIからの利用

1. ライブラリの各曲にある `≋` を押す（または「…」で曲の詳細を開く）。
2. 「この曲に近い曲を探す」を選ぶ。
3. 歌唱キャラクター、作者・投稿者、ジャンル、雰囲気、タグの一致理由を見ながら曲を探す。
4. タイトルを押すとその曲の詳細を表示、リンクを押すとニコニコの動画ページが開きます。

ダッシュボードの「ジャンル」「雰囲気」のランキングはクリックできます。項目を押すと、その条件を指定したライブラリへ遷移します。

## 判定方法

`src/app/related-videos.js` の `recommendRelatedVideos()` は次の情報を使います。

| 特徴 | 加点（最大） | 補足 |
|---|---:|---|
| 歌唱キャラクター一致 | 3.5 / 一致キャラ（2名分まで） | SV、Spicyなどはキャラクターへ名寄せ |
| 作者・投稿者名の一致 | 2.2 / 一致名（2名分まで） | 投稿者＝作曲者とは断定しない |
| ジャンル一致 | 1.6 / 一致カテゴリ（2個まで） | タグに根拠がある場合のみ |
| 雰囲気一致 | 1.3 / 一致カテゴリ（2個まで） | タグに根拠がある場合のみ |
| 共通タグ | 0.6〜2.5 / タグ（3個まで） | 出現頻度が低いタグを高めに評価 |

- 順位が同点の場合は動画IDで固定の順に並べます。
- 元動画自体は候補に含めません。
- `VOCALOID` など一般的で区別に使いにくいタグは一致条件から除外しています。
- メタデータ不足の場合、候補は少なくなります。**曲の実際の音・テンポ・コード進行が似ているという意味ではありません。**
- スコアと理由はサーバーへ送信しません。分析はブラウザ上で完結します。

## ジャンル・雰囲気の根拠

`src/discovery.js` の `genreEvidence()` / `moodEvidence()` が、実際に一致したタグとルール名を返します。
「曲の詳細」画面から、各カテゴリに割り当てられた理由を確認できます。

例：タグに `ボカロック` がある場合、「ジャンル：ロック〈ボカロック〉」と表示します。

動画タイトルや投稿者名から雰囲気を決めることはしません。分析結果に未分類が存在することを許容し、ダッシュボードに分類根拠のある動画件数を表示します。

## 既存データと互換性

- SupabaseのスキーマとRLSは変更しません。
- `src/bridge.js` / Tampermonkeyは変更しません。
- マイリスト登録順、直接登録、差分同期、評価、メモ、保存検索は変更しません。
- 複数ユーザーのデータを混合しないよう、推薦元の候補は `buildLibraryRows(state.library)` だけです。

## 開発とテスト

```bash
npm install
npm test
npm run build
```

分類のルールは `src/discovery.js` の `GENRES` / `MOODS` に、関連度の計算は `src/app/related-videos.js` にあります。
UIとロジックを分けているため、表示を変えずに判定精度を改善できます。

**注意:** テストはモックデータで検証します。分類の正解率を主張するものではありません。実際の音楽に合っているかの評価は引き続き必要です。
