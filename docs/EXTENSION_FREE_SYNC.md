# NICO SHELF v0.16 — Tampermonkeyを使わない公開マイリスト同期

## 対応範囲

- できる: Googleログイン後に、公開マイリストの動画IDとタイトル、表示順をCloudflare Worker経由で取得し、DBとの差分をプレビューしてから明示的に反映する。
- できる: NICO SHELFの同期画面から、公開マイリストURL/IDを指定して新規インポートする。初回にリスト名だけDBに保存し、動画の所属は差分確認後に追加する。
- できない: 非公開マイリスト、ニコニコ本体への動画登録・削除、アカウントに紐づく非公開情報。これらの操作は現行のTampermonkey連携が必要。
- OAuth: ニコニコのOAuth利用例は存在するが、一般開発者によるクライアント発行方法とマイリスト読み書き権限を持つスコープを公式資料で確認できていない。**公開APIをOAuth APIと偽装せず**、利用権限を確認するまで直接登録の移行は実施しない。

## Cloudflare設定（初回に必要）

1. 既存の `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` は引き続き **ビルド時**の環境変数として使用する。
2. Workers & Pages → nico-shelf → Settings → Variables and Secrets（ランタイム変数）に次の2件を追加する。
   - `SUPABASE_URL` = 既存SupabaseのProject URL（例: `https://xlgchlblzssypmeslmsk.supabase.co`）
   - `SUPABASE_PUBLISHABLE_KEY` = 同じプロジェクトの **publishable** キー（`sb_publishable_...` または旧anonキー）
3. **service_role / secretキー、ニコニコのCookie、ニコニコのパスワードを入れない。**
4. `wrangler.jsonc` は `worker/index.js` をWorkerとして使用し、`/api/*` のみサーバー処理へルーティング。従来の `npm run build` と `npx wrangler deploy` でよい。
5. 変数変更後は再デプロイし、NICO SHELFで再ログインして同期を試す。

## 操作

1. NICO SHELFでGoogleログインし、「ニコニコとの差分同期」を開く。
2. 「拡張機能なしで公開マイリストを同期」の対象リストを選ぶ。非公開リストがある場合はチェックを外す。
3. 「公開マイリストを照合する」を押す。
4. 取得完了後、「追加」「削除候補」「表示順の差」を確認する。
5. 「確認して差分を反映」で初めてSupabaseに変更が加わる。
6. 初めてのリストは、同画面の「新しい公開マイリストをURL・IDから追加する」でインポートできる。

## セキュリティ / データ整合性

- Worker APIはSupabaseのログイン済みアクセストークンを `/auth/v1/user` で検証した場合のみ応答する。
- Workerは固定ホスト `nvapi.nicovideo.jp` にだけ通信する。URL入力をfetch先として転送しない（SSRF対策）。
- ニコニコ用Cookie、Googleのアクセストークン、Supabaseの`service_role`をニコニコAPIへ送らない。
- DBへのデータ反映は従来のSupabase RLSと`apply_mylist_snapshot`関数で行い、Workerは書き込みを行わない。
- ページ欠損、ID不正、重複、件数変化、非公開・取得失敗では差分作成を中止する。全リスト一括失敗でもDBは変更しない。
- 非公開のリストを選ぶと処理全体を中止するため、公開リストだけを選び直す。
- ニコニコの公開APIは公式に長期保証されていない。API仕様、認証条件、アクセス制限が変われば取得できない可能性がある。
- サーバー側の乱用対策として、一般公開時にはCloudflareのRate Limitingを組み合わせる。同期頻度や多数ユーザーの上限は運用テスト後に確定する。

## 既知の限界

- CloudflareからのニコニコAPI実接続は、この配布作業環境で検証できていない（モックテストのみ）。
- 同期する動画の登録順はAPIから返される表示順で、実際の登録日時の保証はない。
- 画像・説明文・歌唱者などの動画メタデータ全件取得は行わない。既存のメタデータ補完は引き続きログイン済みニコニコタブを使う。
- 他人の公開リストも閲覧・ローカルDBへの読み取りインポートは可能。ただし、その他人のニコニコマイリストを操作する権限を与える機能ではない。

## 将来の本体直接登録

ニコニコによる正規OAuthクライアントの発行・使用可能なスコープ・マイリストAPIの利用条件を確認できた段階で、次の順番で別バージョンに実装する。

1. アカウント連携の導線と権限説明を作成。
2. OAuth認可コード＋PKCEとサーバー側の安全なトークン管理を設計。
3. 読み取り専用スコープで動作検証。
4. 書き込みスコープの正式な許可を得られた場合に限り、動画登録機能を移植。
5. 成功をニコニコ本体で再取得確認してからDBへ反映。古いTampermonkeyは当面残す。
