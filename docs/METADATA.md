# v0.20.1 メタデータ補完

通常の取得経路は、ブラウザ → 同一オリジンのCloudflare Worker → 既存のRenderゲートウェイ → ニコニコの公開thumbinfoです。Tampermonkeyやニコニコへのログインは不要です。アプリへのGoogleログインは必要です。

## 利用方法

「データと設定」の補完画面から、公開情報取得を選んで実行します。開始時点の補完候補を動画ID単位で重複除去し、1回の操作で順次取得します。リクエスト間は400ms、15件ごとに5秒の休憩を入れて自動継続します。詳細画面からは1動画を補完できます。新規差分同期後の補完は最大5件です。既存の手動修正・VocaDB情報・メモ・評価を保持し、欠損だけを埋めます。取得失敗で動画を削除・非公開と判断することはありません。

タイトル、説明、投稿者、サムネイル、投稿日、動画時間、タグ、再生・コメント・マイリスト数を取得します。公開thumbinfoにない「いいね数」は変更しません。音声解析や再生履歴の収集は行いません。

進捗・成功・失敗・未処理件数と中止ボタンを表示します。ダイアログを閉じても同じタブ内では処理が続き、設定画面から進捗を確認できます。タブを閉じると停止します。保存済みの情報は保持され、次の実行はその時点の補完候補を対象にします。

中止では、待機や情報の読み取りを止めます。DBへ既に送信した保存はその1件を完了してから停止し、成功件数へ含めます。アカウント切替・ログアウト・ライブラリの再取得では旧処理を停止し、旧応答を別アカウントのデータへ書き込みません。

アクセス制限（Worker/IP/アカウント/上流429）では最低60秒、Retry-Afterが長ければその時間（最大1時間）待ち、同じ動画を最大2回再試行します。制限が続く場合や取得・保存エラーが3件連続した場合は停止します。個別動画の公開情報がない場合は失敗件数へ加えて続行します。認証・設定エラーは直ちに停止します。

## 運営者の更新

v0.20.0からの更新で追加SQL・変数は不要です。RenderとCloudflareを同じソースへ更新します。v0.20.0の名前同期SQLが未適用なら、先に `202611230001_mylist_names.sql` を全体実行します。Renderのルートはリポジトリのルート、Build Commandは `npm ci --omit=dev --no-audit --no-fund`、Start Commandは `npm run gateway:start`。fast-xml-parserは通常依存です。ゲートウェイ共有鍵・JWT設定・IP/アカウント制限は既存のものを使います。新しい環境変数はありません。

実際のRender環境からの通信は、その環境でコマンドを実行できる場合、`npm run gateway:probe:metadata -- sm9` でも検証できます。通常は更新後のアプリから1件だけ補完し、RenderのLogsで確認します。`/health` が200でも取得成功は意味しません。最後にログイン済みアプリの動画詳細から補完を試して、Worker経由とDB保存も確認します。

## 固定エンドポイントと制限

- Worker: `GET /api/video-metadata/{sm|nm|so + 1〜12桁}`。任意URL・追加クエリは拒否。リスト取得と同じ認証前IP枠・認証後アカウント枠を共有します。
- Render: `GET /v1/video-metadata/{id}`。共有鍵が必須。取得先は `https://ext.nicovideo.jp/api/getthumbinfo/{id}` に固定し、リダイレクトを追いません。ユーザーのCookieとSupabaseトークンは渡しません。
- 上流12秒、Worker→Render28秒、ブラウザ35秒。XML/JSONはヘッダーがなくても350,000バイトで打ち切ります。DOCTYPE・ENTITY宣言を拒否し、XML構文、動画ID、カウンター、日時、サムネイルホスト、文字数・配列上限を検証します。
- DTOの許可した項目だけを返します。上流の生本文・内部エラー・秘密情報はブラウザへ返しません。ブラウザは補完途中にアカウントやライブラリが変わったら保存を停止します。

## 取得できない場合

削除・非公開・年齢制限等により、この公開取得元が情報を返さない動画があります。非公式の取得元なので、提供内容・利用可否は今後変わる可能性があります。

`UPSTREAM_METADATA_UNAVAILABLE` は公開メタデータなし、`UPSTREAM_ACCESS_DENIED` は取得環境からの接続拒否、`UPSTREAM_RATE_LIMITED` は上流制限です。`GATEWAY_ERROR` はRender更新や接続設定を確認してください。失敗時は既存のDB情報を保持します。取得方法を従来のTampermonkey連携へ切り替えることもできますが、非公開・削除動画の取得を保証するものではありません。

2026-11-23に開発環境からsm9を1件取得し、HTTP 200とXML解析成功を確認しました。Render本番とCloudflare本番の実通信は、このパッケージの検証には含みません。

## HTTP 406の調査結果

v0.20.0はthumbinfoにもNVAPI用ヘッダーと `Accept: application/xml,text/xml` を送信していました。開発環境で、sm29200429に対する旧ヘッダーのHTTP 406を再現し、Acceptを `*/*` に変えた同じヘッダーでは200になりました。最小限の `{ Accept: '*/*' }` でも200となりXMLを解析できたため、この形へ分離しました。公開マイリストのNVAPI用ヘッダーは維持します。修正後のゲートウェイ実装でsm29315733も200を確認しました。提供されたRender本番ログは修正前のため、本番からの成功は更新後の確認が必要です。

Renderでは `[gateway] upstream HTTP error` のstatusが取得元のHTTP番号です。動画情報取得ではWorkerが100〜599の数値だけを中継し、クライアントの診断にも表示します。上流本文、Cookie、認証情報、任意の応答ヘッダーを公開することはありません。
